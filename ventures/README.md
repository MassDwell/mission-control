## Starting a New Venture

### Step 1: Moonshot Creates PRD + Experiment Plan

Moonshot researches the idea and produces:
- Product Requirements Document (PRD)
- Experiment Plan (3-week validation)
- Success metrics

### Step 2: Clawson Creates Change Request

Clawson evaluates and creates a CR:

```markdown
# CHANGE REQUEST: [Venture Name]

## Intent
Build [product description] to [achieve business goal]

## Scope
- New venture: ventures/venture_NNN/
- Technology: [Node.js / Python / Go / etc]
- Timeline: [days/weeks]
- Success metric: [measurable outcome]

## Architecture Plan (Codesmith Will Provide)
[Template for Codesmith to fill in]

## Approval Gate
Clawson: "Approved: codesmith — [venture description]"
```

### Step 3: Codesmith Writes Architecture Plan

Codesmith creates an architecture document:

```markdown
# Architecture Plan — Venture NNN

## Tech Stack
- Runtime: Node.js 20 LTS
- Framework: Express
- Database: PostgreSQL (stubbed, .env var)
- Auth: JWT (placeholder API_KEY in env)

## Task Breakdown for Claude Code

### Task 1: API Scaffold
- Generate Express server with 5 endpoints
- Implement error handling middleware
- Add logging
- Tests: 12 unit tests

### Task 2: Database Layer
- Generate schema (with .env DATABASE_URL)
- Create migration scripts
- Tests: 8 integration tests

### Task 3: Authentication
- Generate JWT middleware
- Implement login endpoint (stub secret)
- Tests: 6 auth tests

### Notes
- API_KEY required (Clawson will add): /credentials/venture_001/api-key
- No hardcoded secrets
- All tests must pass before committing
```

### Step 4: Codesmith Invokes Claude Code

```bash
# Inside ventures/venture_001/

# Task 1: API Scaffold
claude_code:
  "Generate Express TypeScript server with 5 REST endpoints:
   - GET /health
   - POST /leads (create new lead)
   - GET /leads/:id (retrieve lead)
   - PUT /leads/:id (update lead)
   - DELETE /leads/:id (delete lead)
   
   Requirements:
   - All endpoints in src/routes/leads.ts
   - Error handling middleware in src/middleware/errorHandler.ts
   - Tests in tests/api.test.ts (12 tests minimum)
   - Use environment variable API_KEY from .env for auth
   - No hardcoded secrets"

# Claude Code generates:
#   src/server.ts
#   src/routes/leads.ts
#   src/middleware/errorHandler.ts
#   src/types/lead.ts
#   tests/api.test.ts
#   package.json (with dependencies)
```

### Step 5: Codesmith Reviews & Tests

```bash
cd ventures/venture_001/

# Install dependencies
npm install

# Run linter
npm run lint
# Expected: 0 errors

# Run type check
npm run typecheck
# Expected: 0 errors

# Run tests
npm test
# Expected: 12 tests pass

# Review diff
git diff HEAD

# If good: commit
git add -A
git commit -m "Claude Code: venture_001 API scaffold (12 tests pass)"

# If bad: revert
git revert HEAD
# Refine task, try again
```

```

```

## Quality Gates

Every Claude Code output MUST pass:

- [ ] Format check (ESLint, Black, etc.)
- [ ] Lint (no warnings)
- [ ] Type check (TypeScript, mypy, etc.)
- [ ] Unit tests (100% pass)
- [ ] Integration tests (100% pass)
- [ ] Smoke test (app starts, health check passes)
- [ ] No secrets in code (API_KEY, password, token scan)
- [ ] Codesmith diff review (approved)

**If any gate fails:** Revert, refine task, try again.

## FAQ

**Q: Can Claude Code access credentials?**  
A: No. It generates code that reads from environment variables. Secrets are added by Clawson after review.

**Q: What if Claude Code breaks something?**  
A: `git revert`. Back to previous state in <1 minute.

**Q: Can I use Claude Code for OpenClaw core?**  
A: No. Only /ventures/. Core work goes through Codesmith directly (no Claude Code).

**Q: Who's responsible for quality?**  
A: Codesmith. Claude Code generates code; Codesmith reviews, tests, commits.

**Q: How does Clawson approve Claude Code?**  
A: Via CR. Codesmith reports results to Clawson; Clawson updates Mission Control workstreams.
