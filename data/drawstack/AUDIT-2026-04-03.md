# DrawStack Full Application Audit — Workflow, Feature & Functionality Gaps
## Date: 2026-04-03
## Auditor: Codesmith (Engineering Agent)
## Task: CLA-307

---

## Executive Summary

DrawStack is a mature construction draw management SaaS with **three primary portals** (GC, Lender, Subcontractor) plus Inspector and Admin interfaces. The application has **strong foundational architecture**, comprehensive database schema, role-based access control, AI-powered features (invoice parsing, risk scoring, anomaly detection), and a well-structured Next.js 13+ codebase with Prisma ORM.

**Critical Finding:** The most significant gap across all portals is **status transparency**. While the system tracks rich status data (DrawStatus, InvoiceStatus, SubInvoiceStatus, SubApprovalStatus), this information is displayed inconsistently across portals, with no shared visual language. GCs, subcontractors, and lenders see different status labels, different badge styles, and have no unified view of "who needs to act next" in the approval chain.

**Overall Maturity:** 7.5/10 — Production-ready for core workflows, but status visibility and cross-portal communication need significant improvement.

## 1. Portal-by-Portal Analysis

### 1.1 GC Portal (`/dashboard`)

**Strengths:**
- ✅ Rich dashboard with 8 KPIs (Total Loan, Drawn, Pending, Avg Days to Fund, etc.)
- ✅ `DrawStatusPipeline` component provides visual progress (Draft → Submitted → Under Review → Approved → Funded)
- ✅ 4-step draw wizard with AI invoice parsing (Gemini 2.5 Flash)
- ✅ SOV management with CSV import (Builder+ plans)
- ✅ Budget overage detection with visual indicators
- ✅ AI anomaly detection before draw submission
- ✅ Change order management with approval workflow
- ✅ Project document vault with expiration tracking
- ✅ Email notifications for key events (draw approved, funded, rejected, info requested)
- ✅ Trial gate enforcement with upgrade prompts
- ✅ Multi-role support (OWNER, ADMIN, MEMBER)

**Workflow Gaps:**
1. **No unified status view for sub invoices within draws** — GCs can see that a draw includes sub invoices, but there's no clear view of which subs have submitted, which are pending approval, and which are approved. The GC must navigate to separate invoice pages to understand sub status.
2. **Draw period dates not captured in wizard** — The `Draw` model has `periodStart` and `periodEnd` fields, but the 4-step wizard (`app/dashboard/draws/new/page.tsx`) does not include date pickers for these fields. AIA G702 forms require billing period dates.
3. **No draw template/preset system** — GCs creating recurring monthly draws must manually enter all line items each time. No "copy from previous draw" or "create template" feature exists.
4. **Inspector assignment is manual** — The GC must manually invite an inspector per draw. No inspector roster or auto-assignment based on project rules.
5. **No bulk draw actions** — GCs cannot batch-submit multiple draft draws or batch-recall multiple submitted draws.

**Feature Gaps:**
1. **No draw comparison view** — GCs cannot easily compare Draw #1 vs Draw #2 to see line-item deltas or cost escalation trends.
2. **No project-level retainage release workflow** — The system tracks retainage held per draw, but there's no dedicated UI for releasing retainage at project completion.
3. **No draw amendment workflow** — Once a draw is submitted, the GC can only recall it to DRAFT or wait for INFO_REQUESTED. There's no "submit amendment" or "resubmit with corrections" status.
4. **No lender communication history panel** — Comments exist on draws, but there's no project-level lender communication log showing all historical interactions.
5. **No mobile-optimized draw wizard** — The 4-step wizard is desktop-first; mobile users must pinch/zoom through complex SOV tables.

**Functionality Gaps:**
1. **Status badge labels differ from pipeline labels** — `StatusBadge` shows "Action Required" for `INFO_REQUESTED`, but `DrawStatusPipeline` doesn't show this status (maps to UNDER_REVIEW). Inconsistent labeling confuses users.
2. **"Needs Attention" panel on dashboard shows draws by status** — but doesn't indicate *who* needs to act (GC vs lender). A draw in UNDER_REVIEW could be waiting on lender review or GC correction.
3. **Change order workflow doesn't auto-update SOV scheduled values** — Approved change orders increment the loan amount but don't propagate to `SOVLine.scheduledValue`. GCs must manually update SOV lines after a CO is approved.
4. **No visibility into lender portal activity** — GCs cannot see when a lender last viewed a draw or when they began review (UNDER_REVIEW timestamp exists but isn't surfaced).

**Score: 8/10** — Excellent core functionality, but status transparency and workflow shortcuts are missing.

### 1.2 Lender Portal (`/lender`)

**Strengths:**
- ✅ Clean project portfolio view with loan amounts and draw counts
- ✅ Full draw detail view with SOV line-item breakdown
- ✅ `LenderActions` component with strict status transition enforcement (SUBMITTED → UNDER_REVIEW → APPROVED → FUNDED)
- ✅ Comment system for GC communication
- ✅ AI Risk Score Card (Low/Medium/High with risk factors)
- ✅ Document list with download links
- ✅ Email notifications to GC when lender approves/rejects/requests info
- ✅ Funding confirmation modal ("This action cannot be undone")
- ✅ Lender invite redemption flow with `LenderProjectAccess` grant

**Workflow Gaps:**
1. **No batch review capability** — Lenders reviewing 5+ draws must click into each one individually. No "review queue" with side-by-side comparison.
2. **No draw approval template/checklist** — Lenders have no configurable checklist (e.g., "Verify lien waiver uploaded", "Confirm retainage calculation"). Each review is ad-hoc.
3. **No conditional approval** — Lenders can only APPROVE or REJECT. There's no "Approve with conditions" or "Approve pending doc upload" status.
4. **No portfolio analytics** — Lenders cannot see aggregate metrics (total at-risk, average time in review, etc.) across all their projects.
5. **FUNDED status is single-event** — Once a draw is marked FUNDED, there's no "partial funding" or "funding delayed" tracking. Real-world scenario: lender wires $180k of a $200k draw; system shows either APPROVED or FUNDED, no middle ground.

**Feature Gaps:**
1. **No lender template system** — The `LenderTemplate` model exists in the schema with fields for PDF/Excel templates, but there's no UI for lenders to upload their custom draw packet templates or auto-fill them with DrawStack data.
2. **No funding schedule/calendar** — Lenders cannot set a "next funding date" or see a calendar view of upcoming draw deadlines.
3. **No project health dashboard** — Lenders see individual draws but no rollup view of "Project X is 60% through budget, 2 draws behind schedule".
4. **No export to lender's internal system** — No API webhook or export button to push draw data to the lender's loan management system.
5. **No document verification UI** — Lenders can download documents but cannot mark them as "verified" or add notes per document (e.g., "G702 signed, lien waiver missing signature").

**Functionality Gaps:**
1. **Status labels differ from GC labels** — `LENDER_STATUS_LABELS` shows "Pending Review" for SUBMITTED, but GC sees "Submitted". This creates confusion in phone calls ("I see it as Submitted" / "I see Pending Review").
2. **No visibility into GC activity** — Lenders cannot see when a draw was last edited or when the GC last viewed the lender's comment.
3. **"Begin Review" and "Approve Draw" buttons are both action-heavy** — UX issue: both buttons are prominent green CTAs. A lender could accidentally click "Approve" when they meant to start review.
4. **PDF preview opens in new tab** — No inline PDF viewer in the lender draw detail page. Mobile users must download and open in external app.
5. **No draw status history log** — Lenders can see current status but cannot see the full timeline (e.g., "Submitted 3/15, Under Review 3/16, Info Requested 3/18, Resubmitted 3/20").

**Score: 6.5/10** — Core approval workflow is solid, but lacks batch features, status transparency, and lender-specific power tools.

### 1.3 Subcontractor Portal (`/sub` and `/submit/[token]`)

**Dual Portal Problem:**
DrawStack has **two separate sub portals**:
1. **Auth-based portal** (`/sub`) — Requires sign-up, shows all assigned projects, full invoice history
2. **Token-based portal** (`/submit/[token]`) — No auth required, single-project access, AI invoice parsing

**This creates significant UX fragmentation.**

**Strengths:**
- ✅ Token portal has excellent AI invoice parsing with confidence badges
- ✅ Auth portal shows SOV line assignments with billing/payment history
- ✅ Both portals allow invoice submission with line-item mapping
- ✅ Status badges for invoice states (DRAFT, SUBMITTED, APPROVED, FUNDED)
- ✅ Payment tracking with retainage balance display
- ✅ Email notification to GC when sub submits invoice

**Workflow Gaps:**
1. **No unified status view for "my invoice in the draw"** — Subs see their invoice as APPROVED, but they don't know if it's been included in a GC draw yet, if that draw is under lender review, or when funding is expected. The `SubApprovalStatus` enum has `INCLUDED_IN_DRAW`, but this isn't displayed to the sub with context.
2. **No draw timeline visibility** — Subs cannot see "Your invoice was included in Draw #4, which was submitted on 3/15 and is currently under lender review."
3. **No communication channel** — Subs have no way to comment on their invoice or ask the GC questions. The comment system exists on `Draw`, but subs don't have access to it.
4. **No required document workflow in auth portal** — The token portal has a required docs upload section, but the auth portal (`/sub`) doesn't surface `SubRequiredDoc` functionality. Subs using the auth portal can't see if they're missing insurance certs or lien waivers.
5. **No invoice amendment** — Once a sub submits an invoice, they cannot edit it. If the GC rejects it, the sub must create a new invoice with a new ID.

**Feature Gaps:**
1. **No recurring invoice feature** — Subs billing the same amount monthly (e.g., $10k/month for 12 months) must manually create each invoice. No "duplicate previous" button.
2. **No invoice templates** — Subs cannot save an invoice template for commonly billed line items.
3. **No mobile app** — The web portal is mobile-responsive, but subs on job sites would benefit from a native app with offline invoice creation.
4. **No payment forecast** — Subs see "Amount Paid" but not "Expected Payment Date" based on typical draw cycle times.
5. **No retainage release request workflow** — Subs can see retainage held but cannot initiate a release request at project completion.

**Functionality Gaps:**
1. **Two portals with different feature sets** — Token portal has AI parsing and required docs; auth portal doesn't. Subs don't know which one to use.
2. **Auth portal invite email has no project context** — `sendSubInviteEmail` sends a generic sign-up link. After sign-up, subs land on `/sub` with a list of projects, but the email didn't tell them which project they were invited to.
3. **SubInvoiceStatus vs SubApprovalStatus confusion** — The schema has both `SubInvoice.status` (DRAFT/SUBMITTED/APPROVED/REJECTED/FUNDED) and `Invoice.subApprovalStatus` (PENDING/APPROVED/REJECTED/INCLUDED_IN_DRAW). Two overlapping status fields create data inconsistency.
4. **No line-item status visibility** — Subs see total invoice status but not per-line-item status (e.g., "Line 1 approved, Line 2 flagged for clarification").

**Score: 5.5/10** — Functional but fragmented. Status transparency is the biggest gap.

**Functionality Gaps:**
1. **Photo upload has no compression** — Large photos (5MB+ from job site cameras) could slow down uploads. No automatic resize/compression.
2. **No photo annotation** — Inspectors cannot draw arrows or add text overlays to highlight deficiencies.

## 2. Cross-Portal Status Transparency Gap (Priority Finding)

### 2.1 Current Status Implementation

**Draw Status Flow:**
```
DRAFT → SUBMITTED → UNDER_REVIEW → APPROVED → FUNDED
                          ↓
                  INFO_REQUESTED (back to GC)
                          ↓
                      REJECTED
```

**How It's Displayed:**
- **GC Portal:** `DrawStatusPipeline` component shows 5-step visual progress
  - Uses `GC_STATUS_LABELS`: "Draft", "Submitted", "Under Review", "Action Required", "Approved", "Funded"
- **Lender Portal:** `StatusBadge` only (no pipeline)
  - Uses `LENDER_STATUS_LABELS`: "Draft", "Pending Review", "Under Review", "Info Requested", "Approved — Awaiting Funding", "Funded"
- **Sub Portal:** `StatusBadge` with `SubInvoiceStatus` (DRAFT/SUBMITTED/APPROVED/FUNDED)
  - No visibility into the parent draw status

**Problems:**
1. **Inconsistent labels:** GC sees "Action Required", lender sees "Info Requested", same status
2. **No "next action" indicator:** Status shows *where* it is, not *who* needs to act
3. **No timeline view:** Users cannot see history ("How long was it in review?")
4. **No cross-portal visibility:** Subs don't know if their invoice is in a draw under lender review
5. **No escalation tracking:** No "overdue" or "urgent" indicators based on time in status

### 2.2 What's Missing

**User Needs:**
- **GCs:** "Which draws need my action vs which are waiting on lender?"
- **Lenders:** "Which draws need my review vs which are waiting on GC to fix issues?"
- **Subs:** "Is my invoice in a draw yet? When will I get paid?"
- **All users:** "Who owns the next action, and what is it?"

**Technical Needs:**
- Unified status labels across all portals
- Clear "responsible party" (GC / Lender / System / Sub)
- Timestamp for each status transition
- SLA indicators ("In review for 7 days, typical is 3 days")
- Mobile-friendly compact and expanded views

## 3. Unified Status Component Design (Deliverable)

### 3.1 Component Specification

**Component Name:** `ApprovalStatusFlow`

**Purpose:** Display the current state of a draw or invoice approval workflow with:
- Visual progress indicator (breadcrumb-style)
- Current step highlighting
- Next action indicator with responsible party
- Timestamp of each completed step
- Role-appropriate visibility (sub sees their scope, lender sees theirs, GC sees full chain)

**Props:**
```typescript
interface ApprovalStatusFlowProps {
  entityType: 'draw' | 'subInvoice' | 'invoice'
  status: DrawStatus | SubInvoiceStatus | InvoiceStatus
  timestamps: {
    createdAt: Date
    submittedAt?: Date
    reviewStartedAt?: Date
    approvedAt?: Date
    fundedAt?: Date
    rejectedAt?: Date
  }
  viewerRole: 'gc' | 'lender' | 'sub' | 'inspector'
  responsibleParty?: 'gc' | 'lender' | 'sub' | 'system'
  includesSubInvoices?: boolean // for draws with subs
  subInvoiceStatuses?: Array<{
    subName: string
    status: SubApprovalStatus
  }>
  variant?: 'compact' | 'expanded' | 'timeline'
}
```

**Visual Design:**

**Expanded View (Desktop):**
```
┌─────────────────────────────────────────────────────────────────┐
│ Draw #5 Approval Status                                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ✓ Created        ✓ Submitted      ● Under Review   ○ Approved │
│  Mar 1, 10:00a    Mar 3, 2:15p     Mar 4, 9:30a                │
│  by GC            by GC            by Lender                    │
│                                                                 │
│  ════════════════════════════════════════                       │
│                                                                 │
│  Next Action: Lender Review                                     │
│  Waiting on: Capital Bank (lender)                              │
│  In this step for: 2 days (typical: 3 days)                     │
│                                                                 │
│  [View Full Timeline]                                            │
└─────────────────────────────────────────────────────────────────┘
```

**Compact View (Mobile):**
```
┌────────────────────────────┐
│ ● Under Lender Review      │
│ Next: Lender must approve  │
│ In review: 2 days          │
└────────────────────────────┘
```

**Timeline View (Full History):**
```
┌─────────────────────────────────────────────┐
│ Approval Timeline                           │
├─────────────────────────────────────────────┤
│ ✓ Draw Created                              │
│   Mar 1, 10:00am by John Smith (GC)         │
│   ↓ 2 days                                  │
│ ✓ Submitted to Lender                       │
│   Mar 3, 2:15pm by John Smith (GC)          │
│   ↓ 1 day                                   │
│ ● Under Lender Review                       │
│   Mar 4, 9:30am by Sarah Jones (Lender)     │
│   Currently in progress (2 days)            │
│   ↓                                         │
│ ○ Pending: Lender Approval                  │
│ ○ Pending: Funding Confirmation             │
└─────────────────────────────────────────────┘
```

**Role-Specific Views:**

**GC View:**
- Shows full approval chain
- Highlights when action is needed from GC (INFO_REQUESTED, REJECTED)
- Shows lender activity timestamps

**Lender View:**
- Shows submission → review → approval → funding
- Highlights when action is needed from lender
- Does NOT show internal GC draft stages

**Sub View:**
- Shows simplified flow: "Submitted → GC Approval → In Draw → Lender Review → Funded"
- Highlights when sub needs to take action (if REJECTED by GC)
- Links to parent draw status if invoice is INCLUDED_IN_DRAW

### 3.2 Status Mapping & Labels

**Unified Status Labels (All Portals):**

| System Status | Unified Label | GC View | Lender View | Sub View |
|---------------|---------------|---------|-------------|----------|
| DRAFT | Draft | Show | Hide | Show |
| SUBMITTED | Submitted for Review | "Submitted to Lender" | "Pending Review" | "Submitted to GC" |
| UNDER_REVIEW | Under Review | "Lender Reviewing" | "Under Review" | "GC Reviewing" |
| INFO_REQUESTED | Action Needed | "Action Required" | "Awaiting GC Response" | "More Info Needed" |
| APPROVED | Approved | "Approved by Lender" | "Approved — Awaiting Funding" | "Approved" |
| FUNDED | Funded | "Funded" | "Funded" | "Paid" |

**Responsible Party Indicator:**
- Each status has a `responsibleParty` field: `gc`, `lender`, `sub`, `system`
- Visual indicator: colored badge or icon
  - GC: Blue badge
  - Lender: Green badge
  - Sub: Orange badge
  - System: Gray badge

### 3.3 Technical Implementation

**New Database Fields (Migration Required):**
```prisma
model Draw {
  // ... existing fields
  reviewStartedAt DateTime? // timestamp when lender clicks "Begin Review"
  infoRequestedAt DateTime? // timestamp when lender clicks "Request Info"
  rejectedAt     DateTime? // timestamp when lender rejects
}

model DrawStatusHistory {
  id          String      @id @default(cuid())
  drawId      String
  draw        Draw        @relation(fields: [drawId], references: [id])
  fromStatus  DrawStatus
  toStatus    DrawStatus
  changedBy   String      // clerkUserId
  changedByRole String    // "gc" | "lender" | "system"
  timestamp   DateTime    @default(now())
  note        String?     // optional note explaining the transition
  @@index([drawId])
}

model SubInvoice {
  // ... existing fields
  gcReviewedAt   DateTime?
  gcApprovedAt   DateTime?
  includedInDrawAt DateTime? // when added to a draw
}
```

**API Changes:**

1. **New endpoint: `GET /api/draws/[drawId]/status-timeline`**
   - Returns full status history with timestamps and actors
   - Role-filtered response (GC sees all, lender sees relevant steps)

2. **Update `PATCH /api/draws/[drawId]` to record status history:**
   - Create `DrawStatusHistory` record on every status transition
   - Set `reviewStartedAt` when status → UNDER_REVIEW
   - Set `infoRequestedAt` when status → INFO_REQUESTED
   - Set `rejectedAt` when status → REJECTED

3. **New computed field: `responsibleParty`**
   - Logic:
     - DRAFT → `gc`
     - SUBMITTED → `lender`
     - UNDER_REVIEW → `lender`
     - INFO_REQUESTED → `gc`
     - APPROVED → `lender` (until FUNDED)
     - FUNDED → `system`
     - REJECTED → `gc` (if they want to revise)

**Component Files:**

- `components/status/ApprovalStatusFlow.tsx` — main component
- `components/status/StatusBadge.tsx` — refactored to use unified labels
- `components/status/StatusTimeline.tsx` — full history view
- `lib/status-labels.ts` — unified label mapping (replaces `draw-status-labels.ts`)
- `lib/status-utils.ts` — helper functions (e.g., `getResponsibleParty`, `getTimeInStatus`)

## 4. Additional Workflow, Feature & Functionality Gaps

### 4.1 Change Order Workflow

**Current State:**
- Change orders can be created, submitted, approved, rejected
- Approved COs increment `Project.loanAmount`

**Gaps:**
1. **Approved COs don't auto-update SOV scheduled values** — GCs must manually edit SOV lines after CO approval
2. **No CO tracking in draws** — Draws don't show which COs they reflect. A draw with CO #3 incorporated should display "Includes Change Order #3 (+$25k)"
3. **No CO budget allocation** — COs increase total loan amount but don't specify which SOV lines get the additional budget

**Fix:**
- Add `ChangeOrderSOVLine` association (already exists in schema) to the CO creation UI
- On CO approval, auto-increment `SOVLine.scheduledValue` for linked lines
- Add `draw.changeOrders` array to draw detail pages

### 4.2 Invoice Duplicate Detection

**Current State:**
- `Invoice.isDuplicateFlag` field exists
- `lib/duplicate-detection.ts` has logic

**Gaps:**
1. **No UI for duplicate warnings** — GCs don't see "Possible duplicate of Invoice #123" when uploading
2. **No bulk duplicate resolution** — GCs must dismiss duplicates one by one

**Fix:**
- Add duplicate detection modal on invoice upload
- Add bulk actions in `/dashboard/invoices` to dismiss or confirm duplicates

### 4.3 Lien Waiver Workflow

**Current State:**
- `Project.lienWaiverRequired` boolean exists
- `DrawDocument` type includes `LIEN_WAIVER`

**Gaps:**
1. **No lien waiver verification checklist** — GCs can mark a draw as submitted even if lien waiver is required but not uploaded
2. **No lien waiver generation** — GCs must create lien waivers externally (e.g., Word template) and upload as PDF

**Fix:**
- Add pre-submit validation: if `lienWaiverRequired === true` and no `LIEN_WAIVER` document, show warning
- Add lien waiver template generator (PDF with project/draw data pre-filled)

### 4.4 Payment Tracking

**Current State:**
- `Payment` model exists with `amount`, `paidDate`, `method`, `reference`
- Payments are linked to `Invoice`

**Gaps:**
1. **Payments are only tracked at invoice level, not draw level** — GCs fund draws, not individual invoices. The data model allows draw-level funding (`Draw.fundedAt`), but there's no `DrawPayment` model to record partial payments.
2. **No payment schedule** — Lenders cannot set a future payment date

**Fix:**
- Add `DrawPayment` model linked to `Draw`
- Add "Schedule Payment" action in lender portal (sets `scheduledPaymentDate` on `Draw`)
- Expose scheduled payment dates to GCs and subs

### 4.5 QuickBooks Integration

**Current State:**
- `QuickBooksConnection`, `QuickBooksInvoiceSync`, `QuickBooksAccountMapping` models exist
- No UI implementation found

**Gap:**
- **QuickBooks integration is schema-only** — No OAuth flow, no sync UI, no error handling

**Fix:**
- Implement QuickBooks OAuth in `/dashboard/settings/integrations`
- Add "Sync to QuickBooks" button on invoice and draw pages
- Add sync status badges (Synced / Failed / Pending)

### 4.6 Mobile Experience

**Current State:**
- Responsive design with Tailwind, mobile nav burger menu

**Gaps:**
1. **Draw wizard is desktop-heavy** — SOV tables with 5+ columns are hard to navigate on mobile
2. **No native app** — Job site users (subs, inspectors) would benefit from offline-first native app
3. **No photo upload optimization** — Large job site photos (5MB+) slow down uploads

**Fix:**
- Add mobile-optimized draw wizard with card-based line item entry
- Add image compression on upload (client-side with `browser-image-compression` library)
- Consider React Native or Capacitor for v2.0

### 4.7 Email Notifications

**Current State:**
- Email functions in `lib/notifications.ts`: draw submitted, approved, funded, rejected, sub invoice received

**Gaps:**
1. **No lender invite email** (known issue from prior audit)
2. **No digest emails** — GCs with 10+ active draws get 10+ individual emails, no daily summary
3. **No notification preferences** — Users cannot opt out of specific email types

**Fix:**
- Add `sendLenderInviteEmail` function
- Add daily digest email (cron job to batch notifications)
- Add notification preferences page in `/dashboard/settings/notifications`

### 4.8 Analytics & Reporting

**Current State:**
- Dashboard KPIs (8 cards), monthly burn rate chart, project sparklines

**Gaps:**
1. **No export to CSV/Excel** — GCs cannot export draw history, invoice data, or payment records
2. **No custom reports** — No way to generate "All draws in Q1 2026" or "Retainage held by subcontractor"
3. **No lender portfolio analytics** — Lenders see projects individually, no rollup metrics

**Fix:**
- Add "Export" button on draw list, invoice list, project list → CSV download
- Add `/dashboard/reports` page with pre-built report templates
- Add `/lender/analytics` page with portfolio-wide metrics

## 5. Severity Classification

### Critical (P0) — Blocks core workflows
1. **No unified status/approval component** — Users confused about who owns next action

## Appendix A: Status State Machines

### Draw Status Transitions (Enforced by API)

**GC Allowed Transitions:**
- DRAFT → SUBMITTED
- SUBMITTED → DRAFT (recall)
- INFO_REQUESTED → SUBMITTED (resubmit)
- REJECTED → DRAFT (revise)

**Lender Allowed Transitions:**
- SUBMITTED → UNDER_REVIEW (begin review)
- UNDER_REVIEW → APPROVED | INFO_REQUESTED | REJECTED
- APPROVED → FUNDED (confirm funding)

### SubInvoice Status Transitions

**Sub Allowed Transitions:**
- (create) → DRAFT
- DRAFT → SUBMITTED

**GC Allowed Transitions:**
- SUBMITTED → APPROVED | REJECTED
- APPROVED → (include in draw) → INCLUDED_IN_DRAW

**System Transitions:**
- INCLUDED_IN_DRAW → FUNDED (when parent draw is funded)
